【4号站 nav.599568.xyz → Vercel 脱离 CF 测试包】

========== 先回答问题：对收录/审核有没有影响 ==========
URL 全部不变：sitemap 96 条 .html 已逐条核对，包内 0 缺失，
页面内容一字未改，ads.txt / robots.txt / sitemap.xml 原样保留。
Google 收录的 URL 完全一致 → 理论上不影响收录，AdSense 站点记录也不变。

========== 但要清楚这几条风险 ==========
1) DNS 切换有几分钟~几小时生效期，期间部分访客可能打不开
2) 服务器从 CF 边缘节点换成 Vercel，IP 和地理位置变了
   → TTFB 变化，Google 抓取速率可能短暂波动（一般几天内恢复）
3) 国内访问会变慢（失去 CF 的节点）
4) 测完搬回来还要再波动一次
5) _headers 是 CF 专属格式，Vercel 不认；
   已用 vercel.json 的 headers 等价替代（MIME 已钉死）

========== 第一步：Vercel 部署 ==========
vercel.com → Add New → Project → 上传本目录【全部内容】
Framework Preset 选 Other → Deploy
Settings → Domains → 添加 nav.599568.xyz（www 也加）
Vercel 会给出需要的 DNS 记录。

========== 第二步：回 CF 改 DNS ==========
CF 后台 → DNS → Records
  A      @     76.76.21.21（以 Vercel 显示为准）
  CNAME  www   cname.vercel-dns.com
★ 代理状态点成【灰色云 / DNS-only】← 这才是脱离 CF 的动作
★ CF 里的 Worker、路由、Page Rules 都【不要删】，留着回滚

========== 第三步：确认真的脱离了 ==========
打开 https://nav.599568.xyz → F12 → Network → 主文档 Response Headers
  Server: cloudflare  → 没成功
  Server: Vercel      → 成功脱离

========== 判断 ==========
变「已授权」→ 真凶是 CF
仍「未找到」→ 与 CF 无关，问题在 AdSense 侧（撤站重加或提工单）
